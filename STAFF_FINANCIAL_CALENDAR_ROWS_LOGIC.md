# Логика отображения строк в календарной сетке финансовой истории педагога

## Файл реализации

`src/pages/StaffDetail.tsx` → компонент `FinancialCalendarTable`

## Общая концепция

Строки в финансовой календарной сетке появляются из **двух источников**:

1. **Записи из журнала затрат** (`staff_journal`) — всегда отображаются
2. **Активные ручные ставки** (`staff_manual_rate_history`) — отображаются, если нет записей

## Логика появления строк

### Источник 1: Журнал затрат (основной)

```typescript
// useMemo: entriesByRow
journalEntries.forEach((entry) => {
  const activityId = entry.activity_id || "none";
  const mode = entry.is_manual_override ? "manual" : "auto";
  const isGroup = entry.group_lesson_id !== null;
  const rowKey = isGroup
    ? `${activityId}:${mode}:group:${entry.group_lesson_id}`
    : `${activityId}:${mode}:regular`;
  // Создается строка
});
```

**Правило:** Если есть хотя бы одна запись в `staff_journal` за просматриваемый месяц — строка появляется **всегда**.

### Источник 2: Активные ручные ставки (дополнительный)

```typescript
// useMemo: entriesByRow
manualRateHistory.forEach((rate) => {
  // Проверка активности ставки для текущего месяца
  if (
    effectiveFrom <= monthEnd &&
    (!effectiveTo || effectiveTo >= monthStart)
  ) {
    const rowKey = `${activityId}:manual:regular`;
    // Создается пустая строка, если её еще нет
    if (!map.has(rowKey)) {
      map.set(rowKey, new Map());
    }
  }
});
```

**Правило:** Если ручная ставка активна для месяца И нет записей в журнале — создается **пустая строка** для возможности заполнения.

## Логика удаления строк

### ✅ Строка ОСТАЕТСЯ (защита финансовой истории)

**Условие:** Есть записи в `staff_journal` за просматриваемый месяц

**Сценарий:**

```
Январь: создана ручная ставка
Январь: добавлены записи в журнал (1500₴)
Март: ручная ставка удалена

Результат при просмотре января:
✅ Строка ОСТАЕТСЯ с суммой 1500₴
```

**Причина:** Финансовая история защищена от потери, записи с суммами не исчезают.

### ❌ Строка ИСЧЕЗАЕТ (очистка пустых периодов)

**Условие:** НЕТ записей в `staff_journal` за просматриваемый месяц

**Сценарий:**

```
Январь: создана ручная ставка
Февраль: ставка активна, но записей нет
Март: ручная ставка удалена

Результат при просмотре февраля:
❌ Строка ИСЧЕЗАЕТ (была пустая, ставка удалена)
```

**Причина:** Пустые неиспользованные строки не захламляют интерфейс.

## Поведенческая матрица

| Месяц                           | Ставка активна? | Записи в журнале? | Отображение строки   | Примечание               |
| ------------------------------- | --------------- | ----------------- | -------------------- | ------------------------ |
| Январь                          | ✅ Да           | ✅ Да (1500₴)     | ✅ Показать с суммой | История защищена         |
| Февраль                         | ✅ Да           | ❌ Нет            | ✅ Показать пустую   | Готова к заполнению      |
| Март (ставка удалена)           | ❌ Нет          | ❌ Нет            | ❌ Скрыть            | Очистка пустых           |
| Январь (после удаления в марте) | ❌ Нет          | ✅ Да (1500₴)     | ✅ Показать с суммой | **История сохраняется!** |

## Автоматическое обновление

Строки пересчитываются автоматически через `useMemo` при изменении:

```typescript
useMemo(() => {
  // Пересчет строк
}, [
  journalEntries, // Записи изменились
  manualRateHistory, // Ставки изменились
  year, // Сменили год
  month, // Сменили месяц
]);
```

**React автоматически обновляет таблицу** — ручного удаления строк не требуется.

## Типы ручных ставок

Поддерживаются **все** типы ручных ставок:

- `hourly` — почасовая оплата
- `per_session` — за занятие
- `per_working_day` — за рабочий день

Все типы создают строки одинаково, различия только в логике расчета сумм.

## Сценарий использования

### Типичный рабочий процесс:

1. **Январь:** Создали ручную ставку 500₴/занятие
   - Строка появилась сразу (пустая)
2. **Январь:** Отметили 3 занятия
   - Строка показывает 1500₴

3. **Февраль:** Просматриваем
   - Строка пустая, готова к заполнению

4. **Март:** Удалили ставку (педагог уволился)
   - Январь: строка осталась (1500₴ защищены)
   - Февраль: строка исчезла (была пустая)

### Преимущества логики:

✅ **Защита данных** — начисленные суммы никогда не теряются  
✅ **Чистый интерфейс** — пустые строки удаляются автоматически  
✅ **Гибкость** — можно удалять ставки без потери истории  
✅ **Автоматизм** — не требует ручного управления строками
