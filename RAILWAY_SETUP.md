# Пошаговая настройка: логин через Railway (без Supabase)

**Ручной перенос данных и инкрементальное обновление:** см. [docs/MIGRATION_ALTERNATIVES.md](docs/MIGRATION_ALTERNATIVES.md).

**Автопроверка (минимум действий):** из корня проекта выполните `npm run check:railway`. Скрипт сам проверит доступность API, ответ `/api/rest/v1/students` и подключение к БД с подсчётом строк в ключевых таблицах. Код выхода 0 — всё ок, 1 — есть ошибки.

Если при входе вы видите **500 Internal Server Error**, выполните шаги ниже по порядку.

---

## 1. Миграция данных (один раз)

- В корне проекта создайте `.env.migration` с переменными:
  - `SUPABASE_URL` — URL вашего Supabase
  - `SUPABASE_SERVICE_KEY` — сервисный ключ
  - `RAILWAY_DATABASE_URL` — строка подключения к PostgreSQL в Railway (из панели Railway → ваша БД → Connect → Connection URL)

- Запустите миграцию:
  ```bash
  node scripts/migrate-to-railway.js
  ```
  Дождитесь окончания без ошибок.

- **Проверка:** в конце скрипт выведет «Кількість рядків у Supabase (джерело)» и «на Railway (після копіювання)». Если в источнике числа > 0, а на Railway везде 0 — значит, копирование не сработало (посмотрите вывод по каждой таблице: `✓ public.таблица (вставлено/всего)`). Если в Supabase уже 0 — данные нужно брать из старого проекта Supabase или миграцию не запускали ранее; тогда сначала убедитесь, что `SUPABASE_DATABASE_URL` в `.env.migration` — это **строка подключения к БД** (Supabase → Project Settings → Database → Connection string → URI), а не API URL.

---

## 2. Настройка API-сервера

- Перейдите в папку сервера:
  ```bash
  cd server
  ```

- Создайте файл **`server/.env`** (именно в папке `server`), скопируйте в него из `.env.migration` строку подключения и добавьте секрет:
  ```env
  DATABASE_URL=postgresql://...   # то же значение, что RAILWAY_DATABASE_URL
  JWT_SECRET=любая-длинная-случайная-строка
  PORT=3001
  ```

- Установите зависимости (если ещё не ставили):
  ```bash
  npm install
  ```

- Запустите сервер:
  ```bash
  npm run dev
  ```

- В консоли должно появиться:
  - `База даних: підключено` (или «помилка підключення» — тогда проверьте `DATABASE_URL`)
  - `API сервер: http://localhost:3001`

- **Не закрывайте этот терминал.** Сервер должен работать, пока вы входите в приложение.

---

## 3. Создание первого владельца (owner) или установка пароля

**Если пользователь уже есть в БД** (например, перенесён из Supabase), но при входе появляется «Password not set» — установите пароль так:

- В папке `server` выполните (подставьте свой email и пароль):
  ```bash
  cd server
  npm run set-password -- zd@ukr.net ВашПароль
  ```
- Скопируйте выведенный SQL и выполните его в Railway → PostgreSQL → Raw SQL.
- После этого войдите в приложение с этим email и паролем.

**Если пользователя ещё нет** — создайте нового:

- В папке `server` выполните:
  ```bash
  npm run create-first-owner -- zd@ukr.net ВашПароль
  ```
- Выполните выведенный SQL в Railway → Raw SQL.

---

## 4. Настройка фронтенда

- В **корне** проекта (не в `server`) создайте или отредактируйте файл **`.env`**:
  ```env
  VITE_USE_RAILWAY=true
  ```

- Запустите фронтенд (из корня проекта):
  ```bash
  npm run dev
  ```

- Откройте в браузере адрес, который покажет Vite (обычно `http://localhost:8080`).

---

## 5. Вход в приложение

- На странице входа введите **тот же email и пароль**, что использовали в шаге 3 (например, `zd@ukr.net` и ваш пароль).

- Если снова появится ошибка:
  1. Посмотрите **терминал, где запущен сервер** (`npm run dev` в `server`). Там будут строки `[Auth login] ПОМИЛКА:` и «Деталі» — скопируйте этот текст.
  2. В браузере откройте консоль (F12 → Console). При 500 появится лог `[Railway API] 500 відповідь:` с телом ответа — это поможет понять, что вернул сервер.

---

## Частые причины 500 при логине

| Симптом в консоли сервера | Что сделать |
|---------------------------|-------------|
| `База даних: помилка підключення` | Проверить `DATABASE_URL` в `server/.env` (скопировать из Railway, без лишних пробелов/кавычек). |
| `relation "auth.users" does not exist` | Запустить миграцию снова: `node scripts/migrate-to-railway.js`. |
| `Password not set` или `Invalid credentials` | Создать владельца заново: `npm run create-first-owner -- email@example.com Пароль` и выполнить выданный SQL в БД Railway. |
| В консоли сервера ничего нет при нажатии «Войти» | Сервер не запущен или фронтенд обращается не туда. Убедитесь, что в одном терминале запущен `cd server && npm run dev`, а в браузере открыт сайт с Vite (порт 8080). |

---

## Предупреждения React Router в консоли

Сообщения про **React Router Future Flag** (`v7_startTransition`, `v7_relativeSplatPath`) — это предупреждения о будущей версии маршрутизатора. На логин они не влияют. При желании их можно отключить, добавив соответствующие флаги в конфигурацию React Router.
