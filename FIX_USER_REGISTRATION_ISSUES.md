# Исправление проблем с регистрацией пользователей

## Обнаруженные проблемы

### 1. Новый пользователь получил роль Owner вместо Viewer/Newregistration

**Причина:** Триггер базы данных `handle_new_user_profile()` определял первого пользователя по условию `profiles_count = 0` (количество профилей равно нулю). Если в базе не было профилей (или они были удалены), новый пользователь мог получить роль owner.

### 2. Имя пользователя не сохранилось

**Причина:** Триггер читает `raw_user_meta_data` в момент создания пользователя, но эти данные могут быть записаны с задержкой. Также порядок полей в COALESCE был неоптимальным.

---

## Решение

### Шаг 1: Применить миграцию базы данных

Откройте Supabase Dashboard → SQL Editor и выполните содержимое файла:

```
supabase/migrations/20260207000000_fix_user_profile_creation_logic.sql
```

**Что изменилось:**

- ✅ Теперь триггер проверяет наличие **существующего owner** (не просто считает профили)
- ✅ Только если в системе НЕТ owner, новый пользователь станет owner
- ✅ Изменен порядок чтения метаданных: сначала `parent_name`, потом `full_name`, потом `name`
- ✅ Добавлено логирование в PostgreSQL для отладки

### Шаг 2: Исправить проблемного пользователя

Выполните SQL из файла `FIX_WRONG_USER_ROLE.sql` в Supabase SQL Editor:

1. **Проверьте текущую ситуацию** (запрос 1) - увидите всех пользователей
2. **Найдите проблемного пользователя** (запрос 2) - owner без имени
3. **Исправьте пользователя** (запрос 3) - UPDATE для пользователя `704f0301-a901-49cd-9b92-4edabe370037`
4. **Проверьте результат** (запрос 4)

**Что произойдет:**

- Роль изменится с `owner` на `newregistration`
- `is_active` изменится на `false` (требует активации админом)
- Имя заполнится из `raw_user_meta_data` (parent_name и child_name)

### Шаг 3: Активировать пользователя через интерфейс

1. Перейдите в раздел **"Користувачі"** (Пользователи)
2. Найдите исправленного пользователя (теперь с именем)
3. Измените роль на нужную (например, `parent` или `viewer`)
4. Включите переключатель активности (toggle)
5. Сохраните изменения

## Проверка после исправления

### Тест 1: Регистрация нового пользователя

1. Создайте нового пользователя через форму регистрации
2. Укажите email, пароль, ФИО родителя и ребенка
3. Проверьте в панели "Користувачі":
   - ✅ Имя должно отображаться (ФИО родителя)
   - ✅ Роль должна быть `newregistration`
   - ✅ Статус `is_active` = `false` (неактивен)

### Тест 2: Проверка существующего owner

Убедитесь, что в системе есть только ОДИН пользователь с ролью `owner`:

```sql
SELECT up.id, u.email, up.full_name, up.role, up.is_active
FROM user_profiles up
JOIN auth.users u ON u.id = up.id
WHERE up.role = 'owner';
```

Должен быть только **ОДИН** результат - ваш основной аккаунт.

## Логи для отладки

Теперь при создании пользователя в PostgreSQL логах появится сообщение:

```
NOTICE: Created user profile for user <UUID> with role <ROLE> and metadata: parent_name=<NAME>, child_name=<NAME>
```

Чтобы посмотреть логи:

1. Supabase Dashboard → Logs → Postgres Logs
2. Фильтр: последние 1-2 часа
3. Ищите NOTICE или WARNING с текстом "Created user profile"

## Что делать, если проблема повторится

1. **Проверьте, применена ли миграция:**
   ```sql
   SELECT * FROM public.handle_new_user_profile();
   ```
2. **Проверьте user_metadata при регистрации:**

   ```sql
   SELECT id, email, raw_user_meta_data
   FROM auth.users
   WHERE id = '<USER_ID>';
   ```

3. **Проверьте PostgreSQL логи** на наличие WARNING/ERROR при создании профиля

4. **Проверьте консоль браузера** на наличие логов `[Auth]` при регистрации

## Дополнительная информация

### Почему используется роль 'newregistration'?

- Безопасность: новые пользователи не могут сразу получить доступ к системе
- Контроль: администратор должен проверить и активировать нового пользователя
- Гибкость: администратор может назначить нужную роль (parent, viewer, manager и т.д.)

### Кто должен быть owner?

- Только **первый пользователь**, создавший систему
- Обычно это владелец бизнеса или технический администратор
- В системе должен быть **только ОДИН** owner

### Роли в системе:

- `owner` - полный доступ ко всему
- `admin` - все, кроме управления owner
- `manager` - дети, журналы, оплаты
- `accountant` - финансы, отчеты
- `viewer` - только просмотр
- `parent` - кабинет родителя (свои дети)
- `newregistration` - ожидание активации
